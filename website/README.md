# Website

The marketing site for the app. It is built with Vite, vanilla JS and GSAP (ScrollTrigger, SplitText, DrawSVG) on native scroll, and served as static assets on Cloudflare Workers, with one tiny Worker for `/download`.

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # sync config, vite build into dist/, then check:name and check:size
npm run shots        # build, then screenshot the page into shots/
npm run check:name   # fail if the product name is hard-coded anywhere
npm run check:size   # fail if the shipped JS is over 115 kB gzip
npm run test:worker  # unit-test the /download Worker (mocked fetch + Cache API)
npm run deploy:check # build, then wrangler deploy --dry-run
npm run deploy       # build, then npx wrangler deploy
```

## Renaming

The name, slug, domain and links all live in `site.config.json`. To rename, change that file and run `npm run build`.

The build then:

- regenerates `wrangler.jsonc` (the Worker name and the custom-domain route)
- regenerates `public/site.webmanifest`
- re-renders `og.png` and the favicons with Edge or Chrome
- replaces every `{{token}}` in the HTML

JS reads the name through `import config from './config.js'`.

## Deploy (Cloudflare Workers static assets + a /download Worker)

- The `sriharan.me` zone must be on the same Cloudflare account. The custom domain is created on the first deploy.
- `wrangler.jsonc` is generated by `npm run sync`, which every build runs. Its `main` points at `worker/index.js`, and `assets.run_worker_first` is `["/download", "/download/"]`, so the Worker only runs for that one path. Everything else is served straight from `dist/` through the `ASSETS` binding.
- Every Download button links to `/download` (the `apk` field in `site.config.json`), never to an APK file name. The Worker reads the latest GitHub release, caches that answer for 10 minutes with the Cache API, and 302-redirects to the release's first `.apk` asset. When a release has several APKs it prefers a universal build, then one not tied to a CPU architecture. If the API fails or there is no `.apk`, it redirects to the releases page instead. Locally, `vite dev`, `vite preview` and the screenshot server redirect `/download` to the releases page.
- `public/_headers` sets long-lived caching for `/assets/*` and the security headers. The build adds the CSP hash for the inline boot script.
- `public/404.html` is served for misses (`not_found_handling: "404-page"`).

## Layout

| Path | What it is |
|---|---|
| `index.html` | Section shells. Each `<!-- scene:<id> -->` marker inlines `src/scenes/<id>.html`. |
| `src/main.js` | Boot: ScrollTrigger, then each `src/scenes/<id>.js` `init(ctx)` in document order. |
| `src/lib/` | `thread` (the dashed route), `traveler` (the orange dot), `hud`, `fx`, `pin`, `seams` (map crossfades between stages), `loop` (per-frame work that sleeps when the page is idle), `world`, `phone`, `env`. |
| `src/styles/` | `tokens.css` / `tokens.js`, base, type, layout (stage layers, grid, map styles), components, thread. |
| `src/components/` | Pure string builders used at build time and at runtime (`logo`, `icon`). |
| `src/partials/` | Sprites (the generated `#world` map symbol), top bar, footer, phone template. |
| `scripts/` | `sync-config`, `render-assets`, `shot`, `scene`, `check-name`, `gen-world`. |
| `worker/` | The `/download` Worker and its tests. |

## Working on one scene

1. Edit only `src/scenes/<id>.{html,js,css}`.
2. Run `node scripts/scene.mjs <id>`. It builds into `.tmp/<id>/dist` and saves screenshots of that scene's scroll window into `.tmp/<id>/shots`.
3. Add `--reduced` for the reduced-motion end frames, or `--nojs` to check the no-JS fallback.

The command exits non-zero on any console error, page error, failed request or horizontal overflow, and on broken story invariants (for example, scene 03's copy or PARKED showing before the drive reaches them).

`?shots` in the URL makes the page deterministic for screenshots: scrubs jump, snaps and idle loops are off, and punches finish instantly. `?reduced` forces the reduced-motion path, and `?debug` shows ScrollTrigger markers.
